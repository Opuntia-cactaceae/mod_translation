# **Чекпоинт 4**

## **Создание приложения на FastAPI**

В приложении есть поддержка:

- регистрации и аутентификации пользователей;
- перевода одной фразы и батча фраз;
- хранения истории переводов в базе данных;
- административных операций (просмотр пользователей/переводов, статистика, удаление истории пользователя с подтверждением).

Суть проекта и решения — это сервис перевода текстов локализации (в первую очередь игровых), где важно не только перевести текст, но и сохранить служебные конструкции: цветовые теги, переменные, плейсхолдеры и системные выражения. Такие элементы не должны быть изменены моделью, иначе результат станет непригодным для использования в игре или приложении.


Приложение решает эту задачу следующим образом:

- перед отправкой текста в LLM служебные токены и теги маскируются;
- после получения ответа они восстанавливаются в исходном виде;
- результат дополнительно проверяется на целостность структуры тегов;
- если структура нарушена, перевод помечается статусом corrupted, но все равно возвращается клиенту (HTTP 200), чтобы клиент мог принять решение самостоятельно.



Примеры типовых запросов, для которых предназначен сервис:

```
{
  "request_id": "Teto",
  "source_text": "§RКасане Тето§! — это подружка §BХацунэ Мику§!.",
  "source_lang": "ru",
  "target_lang": "en",
  "model_id": "llama-3.3-70b-versatile"
}
```

Результат перевода:

```
{
  "request_id": "Teto",
  "translated_text": "§RKasane Teto§! is a friend of §BHatsune Miku§!.",
  "status": "ok",
  "error_message": null
}
```

Пример более сложного текста с переменными, плейсхолдерами и переносами строк:

```
{
  "request_id": "3334333333",
  "source_text": "Привет $USER_NAME$! §YWarning§!: Планета [Root.GetName] имеет {VALUE}% нестабильности.\n",
  "source_lang": "ru",
  "target_lang": "en",
  "model_id": "llama-3.3-70b-versatile"
}
```

Результат перевода:

```
{
  "request_id": "3334333333",
  "translated_text": "Hello $USER_NAME$! §YWarning§!: Planet [Root.GetName] has {VALUE}% instability.",
  "status": "ok",
  "error_message": null
}
```

На данный момент перевод реализуется только при помощи моделей от сервиса [Groq](https://groq.com). (выбранный бейслайн и проверка одной из гипотез проекта) Приложение построено с возможностью использования разных сервисов (и потенциально локальных в том числе). Для этого достаточно реализовать интерфейс ModelRoutedTranslator и зарегистрировать новую реализацию в translation_gateway/registry.py. 

## **Основные возможности и ключевая логика**

### **1) Идемпотентность переводов**

Перевод идентифицируется парой (user_id, request_id) и сохраняется в БД.

Если повторить запрос /translate или элемент в /translate/batch с тем же request_id, API вернет уже сохраненный результат, не обращаясь к провайдеру повторно.

### **2) Статус результата перевода**

Результат перевода содержит status:

- ok — перевод корректный;
- corrupted — перевод выполнен, но разметка/теги в результате повреждены (возвращается обычный HTTP 200, без исключения).

Проверка повреждения выполняется на стороне провайдера (Groq) через метрики целостности тегов (tag_integrity.py, эта проверка - часть метрики оценки качества перевода).


### **3) Аутентификация**

- Используется JWT-пара: access и refresh (рефреш ручки пока нет, нужно логиниться заново).
- Refresh-сессии хранятся в БД (таблица refresh_sessions).
- Для админского удаления истории есть отдельный confirm JWT (короткоживущий токен подтверждения), который передается в заголовке.


### **4) Rate limiting и корреляция запросов**

- Middleware корреляции запросов (CorrelationIdMiddleware).
- Middleware маппинга исключений в HTTP-ответы (ExceptionMapperMiddleware).


## **Как устроена архитектура**

Архитектура разделена на 4 слоя: api -> application -> domain -> infrastructure.

### **API слой (app/api)**

Отвечает за HTTP:

- routers/ — маршруты:

  - auth.py — регистрация/логин;
  - translate.py — перевод одного текста и батч;
  - history.py — история переводов;
  - meta.py — языки и модели;
  - admin.py — административные операции.


- schemas/ — Pydantic-схемы входа/выхода (Pydantic используется только на уровне API).

- middlewares/ — middleware: correlation id, rate limit, exception mapping.

- deps.py — зависимости DI: UoW, gateway, jwt_service, password_hasher, admin_read, current_user.



### **Application слой (app/application)**

Содержит бизнес-логику и сценарии (use-cases), не зависящие от ORM:

- translations/use_cases.py:

  - TranslatePhrase — перевод одного текста (валидация, идемпотентность, вызов gateway, сохранение);
  - TranslateBatch — пакетный перевод (валидация батча, идемпотентность по элементам, сохранение, сохранение порядка).


- auth/use_cases.py:

  - RegisterUser, LoginUser — регистрация, логин, выпуск JWT-пары, запись refresh-сессии.

- history/use_cases.py — получение истории переводов.

- meta/use_cases.py — получение языков и моделей через gateway.

- admin/use_cases.py — удаление истории пользователя, глобальная статистика.

- common/ports.py — порты (интерфейсы) для gateway и репозиториев.

- common/uow.py — интерфейс Unit of Work.

- common/errors.py — ошибки application-уровня.

- common/types.py — общие типы (например, режим ожидания, формат ключей и т.п.).

### **Domain слой (app/domain)**

Содержит доменные сущности и value objects:

- users/ — User, ошибки, value objects (например Email).

- translations/ — TranslationRequest, ошибки, value objects: RequestId, LanguageCode, ModelId.

  Value objects проверяют формат данных. Allowlist языков/моделей проверяется на уровне application через gateway.

### Infrastructure слой (app/infrastructure)

**База данных (infrastructure/db)**

- orm_models.py — SQLAlchemy модели (UserORM, TranslationRequestORM, RefreshSessionORM).
- repositories.py — репозитории для пользователей, переводов, refresh-сессий.
- mappers.py — преобразование ORM <-> domain.
- uow.py — SqlAlchemyUnitOfWork: поднимает репозитории и управляет транзакцией.
- admin_read.py — read-only доступ для админских списков/агрегатов (SELECT без доменной логики).
- migrations/ — Alembic-миграции.

**Security (infrastructure/security)**

- jwt_service.py — выпуск/проверка access/refresh JWT и confirm JWT для админских операций.
- password_hasher.py — bcrypt хэширование паролей.

**Translation gateway (infrastructure/translation_gateway)**

- interfaces.py — интерфейс ModelRoutedTranslator (провайдеры).
- registry.py — composition root: собирает список доступных провайдеров.
- adapter.py — TranslationGatewayAdapter: маршрутизирует по model_id, нормализует provider_keys, агрегирует модели/языки.
- translators/groq_translator.py — провайдер Groq: ретраи, backoff, ротация ключей, локальный throttle, защита/восстановление токенов, проверка целостности перевода.
- tag_integrity.py — расчет метрик сохранности тегов/разметки.



## **Структура проекта**

Корень проекта:

- app/ — исходный код приложения.
- create_admin.py — вспомогательный скрипт создания администратора.

Дерево модулей:

- app/main.py — создание FastAPI приложения и подключение роутеров/middleware.
- app/settings.py — конфигурация через переменные окружения.
- app/logging.py — настройка логирования.
- app/api/... — HTTP слой.
- app/application/... — use-cases и порты.
- app/domain/... — сущности и value objects.
- app/infrastructure/... — БД, безопасность, gateway переводчика, rate limit.

## **Переменные окружения (.env)**

Конкретный список переменных определяется app/settings.py (класс Settings). Типовая конфигурация включает:

### **База данных**

- DATABASE_URL — строка подключения к БД (Async SQLAlchemy).

### **JWT и безопасность**

- JWT_SECRET — секрет подписи JWT.
- JWT_ALGORITHM — алгоритм подписи (например, HS256).
- JWT_ACCESS_TTL_SECONDS — TTL access токена.
- JWT_REFRESH_TTL_SECONDS — TTL refresh токена.

### **Провайдер перевода (Groq)**

- APP_GROQ_MODELS — список идентификаторов моделей Groq, доступных для использования в API;

- APP_GROQ_LANGUAGES — список поддерживаемых языков перевода;

- APP_GROQ_MAX_ATTEMPTS — максимальное количество попыток перевода при временных ошибках;

-	APP_GROQ_BACKOFF_BASE_SECONDS — базовая задержка (в секундах);

-	APP_GROQ_BACKOFF_MAX_SECONDS — максимальная задержка при повторных попытках;

- APP_GROQ_RATE_LIMIT_TPS — локальное ограничение частоты запросов к провайдеру (запросов в секунду).



## **Как запустить проект**

### **1) Установка зависимостей**

- Установить зависимости из requirements.txt.

### 2) Настройка окружения**

- Создать файл .env в корне проекта (шаблон _env).
- Указать как минимум параметры БД, используется Postgres, **должна быть таблица app**.

### **3) Инициализация базы данных**

- Применить миграции Alembic из app/infrastructure/db/migrations.

### **4) Запуск приложения**

- Запустить ASGI-сервером (например, uvicorn app.main:app --reload).
- После запуска доступна документация OpenAPI по стандартным путям FastAPI (Swagger UI http://127.0.0.1:8000/docs).

### **5) Создание администратора**

- Запустить create_admin.py (скрипт создает пользователя-админа в БД).

### **6) Создание ключа апи на groq.com**

- Получить бесплатный API ключ на https://console.groq.com/keys.

### **7) Логин**

- Зайти по кредам админа через /auth/login.
- Скопировать токен и вставить в поле (без Bearer).

## **Краткое описание API**


- POST /auth/register — регистрация.
- POST /auth/login — логин, выдача access/refresh.
- POST /translate — перевод одного текста (идемпотентность по request_id).
- POST /translate/batch — пакетный перевод (идемпотентность по request_id каждого элемента).
- GET /history — история переводов текущего пользователя.
- GET /meta/languages — список языков.
- GET /meta/models — список моделей.
- GET /admin/users — список пользователей (admin).
- GET /admin/translations — список переводов (admin).
- GET /admin/stats — агрегированная статистика (admin).
- POST /admin/history/confirm — получить confirm JWT для удаления истории пользователя (admin).
- DELETE /admin/history — удалить историю пользователя, требуется X-Confirm-Token (admin).
