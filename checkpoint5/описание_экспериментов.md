Описание пресетов промптов для экспериментов

---

Базовый пресет: strict_json_v1

Идентификатор
* prompt_id: strict_json_v1
* profile_name: strict_json_batch

Полный состав промпта

Batch system prompt

You are a professional translation engine.
Translate each input item from {src_lang} to {dst_lang}.
Preserve placeholders, markup, special tokens, escaped sequences, and structural formatting exactly.
Do not explain anything.
Return only a valid JSON array of translated strings in the same order as input.
Array length must exactly match the number of input items.
Output must be machine-parseable.

Batch user template

Translate the following JSON array from {src_lang} to {dst_lang}.
Preserve placeholders, tags, variable names, line breaks, and non-translatable system fragments exactly.
Return only a JSON array.

{texts}

Single system prompt

You are a professional translation engine.
Translate the text from {src_lang} to {dst_lang}.
Preserve placeholders, markup, special tokens, escaped sequences, and structural formatting exactly.
Do not explain anything.
Return only the translation.

Single user template

Translate from {src_lang} to {dst_lang}.
Preserve placeholders, tags, variable names, line breaks, and non-translatable system fragments exactly.

{text}

Почему этот пресет выбран базовым

strict_json_v1 задает наиболее жесткий и формализованный вариант поведения модели:
	1.	Перевод должен быть пригоден для автоматической обработки.
	2.	Формат батч-ответа должен быть строго JSON-массивом.
	3.	Количество элементов на выходе должно в точности совпадать с количеством входных элементов.
	4.	Плейсхолдеры, теги, служебные токены, экранированные последовательности и структурное форматирование не должны изменяться.

Именно поэтому этот пресет удобно использовать как точку отсчета. Он минимизирует неоднозначность интерпретации задачи со стороны модели и хорошо подходит для сценариев, где важны:
* стабильный машинно-разбираемый результат;
* корректная пакетная обработка;
* высокая сохранность технических фрагментов строки;
* снижение вероятности лишнего текста, комментариев и нарушений формата.

По сути, это базовый строгий вариант для экспериментов.

Пресет natural_v1

Отличия относительно strict_json_v1
	1.	В системных инструкциях добавлен акцент на естественность формулировок для носителя языка:
* Keep the meaning accurate and the wording natural for native speakers.
	2.	В пользовательском шаблоне батча явно сказано:
* перевод должен быть естественным;
* при этом нетранслируемые служебные фрагменты должны сохраняться без изменений.
	3.	В одиночном режиме инструкция также смещена в сторону естественного и точного перевода:
* naturally and accurately.
	4.	Из формулировок убрана наиболее жесткая фиксация на машинной разборчивости, равенстве длины массива и подчеркнутой строгости формата, которая была явно выражена в базовом пресете.

Почему такой промпт

Он позволяет проверить, помогает ли смещение акцента с формальных требований на естественность перевода улучшить качество текста.
---

Пресет literal_safe_v1

Отличия относительно strict_json_v1
	1.	Модель позиционируется не как просто профессиональный переводчик, а как:
* You are a careful technical translation engine.
	2.	Добавлено прямое указание на консервативный (ну типа с большей опорой на исходный текст) стиль перевода:
* Translate ... conservatively.
	3.	Перечень защищаемых элементов расширен и сформулирован более технически:
* variable names, identifiers, formatting, and all special fragments exactly.
	4.	Явно указано предпочтение буквальной точности над стилистической переработкой:
* Prefer literal accuracy over stylistic paraphrase.
	5.	В пользовательских шаблонах прямо запрещается переписывание системных фрагментов:
* Do not rewrite system fragments.

Почему он выбран таким

Для проверки гипотезы о том, что часть ошибок возникает не из-за нарушения формата JSON, а из-за слишком свободной интерпретации текста моделью. В таком случае проблема не в структуре ответа, а в степени перефразирования.

Поэтому literal_safe_v1 нужен как более консервативная альтернатива:
* он должен уменьшать риск нежелательной стилистической переработки;
* он должен лучше сохранять идентификаторы, переменные и технические формулы;
* он подходит для строк, где буквальная близость к оригиналу важнее формулировок.

В противовес предыдущему промпту

Пресет placeholder_strict_v1

Отличия относительно strict_json_v1
	1.	Основной акцент перенесен с общей строгости JSON-формата на абсолютную неизменность плейсхолдеров и системных токенов.
	2.	В системном батч-промпте введен отдельный блок критического правила:

CRITICAL RULE:
DO NOT MODIFY placeholders or system tokens.

	3.	Добавлены явные примеры защищаемых фрагментов:

$VALUE$, {{0}}, %d, <tag>, [ID]

	4.	В одиночном системном промпте это же требование повторено в компактной форме.
	5.	Одиночный пользовательский шаблон предельно сокращен и содержит только:

{text}

То есть вся логика инструкции вынесена в системный промпт, а пользовательский ввод оставлен максимально чистым.

Почему он выбран таким

Этот пресет нужен для отдельной проверки: достаточно ли сделать центральным именно требование неизменности тегов, чтобы снизить число критических ошибок на технических строках.

Его смысл в следующем:
* базовый пресет распределяет внимание между несколькими требованиями сразу;
* placeholder_strict_v1 концентрирует внимание модели почти на одной задаче — не трогать служебные конструкции;
* примеры плейсхолдеров помогают модели распознавать типовые шаблоны, которые нельзя изменять.

(Тут еще не отключена замена тегов на заглушки с <>)

Пресет fewshot_1_v1

Отличия относительно strict_json_v1
    1.	Инструкции в целом короче и менее формализованы.
	2.	Добавлен один демонстрационный пример перевода.

Для батч-режима:

Example:
Input: Gain $VALUE$ energy
Output: Получите $VALUE$ энергии

Для одиночного режима:

Gain $VALUE$ energy -> Получите $VALUE$ энергии

	3.	Основная ставка сделана не на подробное перечисление ограничений, а на показ образца корректного поведения.
	4.	Из базового варианта убраны более строгие формулировки про машинную разборчивость, точное совпадение длины массива и дополнительные ограничения на формат ответа.

Почему он выбран таким

Этот пресет нужен для проверки полезности few-shot-подхода даже в минимальном объеме. Гипотеза здесь простая: иногда модели легче следовать образцу, чем длинному набору инструкций.

Причины выбора именно такого вида:
* пример короткий и понятный;
* в нем одновременно показаны и сам перевод, и правильное сохранение плейсхолдера $VALUE$;
* он не перегружает промпт, но задает модели нужный паттерн поведения.

Важный момент в том что пока не отключена замена токенов типа $VALUE$ на плейсхолдеры. По сути модель токены из примера в тексте видеть не будет.
Так проверяем влияние точного формата токенов на поведение модели, если формат не важен, то и искать и заменять теги смысла нет, нужно просто пример указать.
Но это еще отдельно будет проверено

---

Итоговая логика набора пресетов

Весь набор покрывает разные экспериментальные гипотезы относительно поведения модели.
* strict_json_v1 — строгий базовый вариант для надежного формата и сохранности структуры.
* natural_v1 — проверка, дает ли более естественная формулировка лучший перевод.
* literal_safe_v1 — проверка, помогает ли более консервативная и буквальная постановка задачи.
* placeholder_strict_v1 — проверка, достаточно ли усилить именно контроль над плейсхолдерами и системными токенами.
* fewshot_1_v1 — проверка, работает ли показ одного примера лучше длинного набора инструкций.

В таком виде пресеты образуют не случайный набор, а небольшую матрицу экспериментальных вариантов, где меняются отдельные акценты:
* строгость формата;
* естественность языка;
* буквальность перевода;
* защита плейсхолдеров;
* наличие демонстрационного примера.

Почему этот пресет выбран базовым

Этот пресет является развитием natural_v1, но с добавлением нескольких демонстрационных примеров. Он сочетает:
* требование естественного перевода;
* строгую неизменность токенов;
* явное обучение через примеры.

Он выбран базовым, потому что:
	1.	Примеры покрывают разные типы токенов (переменные, числовые плейсхолдеры, разметка).
	2.	Модель получает конкретный паттерн поведения, а не только текстовые инструкции.
	3.	Сохраняется баланс между естественностью и контролем структуры.

На этом этапе защита полностью отключена, на вход модели идет сырой текст

* примеры, близкие к реальным данным, дают лучший перенос поведения.

Он нужен, чтобы понять, влияет ли контекст задачи (game localization) на результат сильнее, чем общая формулировка.
