# 1. Назначение

Проект предназначен для проведения экспериментов по машинному переводу с использованием языковых моделей.

Он позволяет:
* запускать эксперименты перевода по заданному набору данных;
* сохранять детальные результаты выполнения;
* вычислять несколько срезов метрик качества и стабильности(апи);
* формировать сводные отчёты и сравнения между экспериментами.

Все параметры эксперимента задаются через JSON-конфигурацию.

---

# 2. Общая схема работы

Основной процесс выполнения:

конфигурация -> перевод -> сохранение -> оценка -> отчёт

Детализированная цепочка:

CLI -> загрузка конфигурации -> выполнение перевода -> сохранение в БД -> вычисление метрик -> построение отчётов

Ключевые свойства системы:
* управление через конфигурацию;
* выбор компонентов через реестры (ака заведение модуля и указание его названия в конфиге);
* поддержка прошлой (модулей по вычислению метрик перевода и самого перевода из чекпоинта 3) логики через адаптеры;
* использование SQLite в качестве основного хранилища.

# 3. Основные команды

подробнее про запуск в [описание_запуска_и_конфигов.md](описание_запуска_и_конфигов.md)

## 3.1. Запуск эксперимента

```
python -m translator_benchmark.cli.main run-experiment <path_to_config.json>
```

## 3.2. Оценка эксперимента

```
python -m translator_benchmark.cli.main evaluate-experiment --experiment-id <id>
```

или

```
python -m translator_benchmark.cli.main evaluate-experiment --config <config.json>
```

## 3.3 Дополнительные команды

* experiment-summary — сводный отчёт по эксперименту
* leaderboard — сравнение экспериментов
* api-summary — метрики работы API
* evaluate-classic — классические метрики перевода
* classic-summary — отчёт по классическим метрикам
* list-registry — список доступных компонентов

# 4. Структура проекта

## 4.1 CLI

`cli/`

Назначение:
* определение команд;
* загрузка конфигурации;
* инициализация окружения;
* запуск процессов перевода или оценки.

---

## 4.2 Конфигурация

`config/`

Назначение:
* описание схем конфигурации эксперимента;
* загрузка JSON-конфигураций;
* получение параметров из переменных окружения.

Конфигурация определяет:
* источник данных;
* модель и параметры вызова;
* шаблоны запросов;
* стратегию защиты (замены на плейсхолдеры);
* правила валидации (ответа от ллмки).

---

## 4.3 Выполнение перевода

`translation/`

Функции:
* загрузка строк из набора данных;
* защита тегов (служебных токенов);
* группировка в батчи;
* вызов модели;
* валидация ответа;
* переход на поштучный режим при ошибках;
* восстановление защищённых элементов;
* сохранение результатов.

---

## 4.4 Взаимодействие с моделями

`runtime/`

Назначение:
* выполнение вызовов API моделей;
* управление ключами доступа (арбузинг лимитов);
* обработка ограничений (rate limit и timeout);
* повторные попытки;
* переключение моделей при ошибках.

---

## 4.5 Формирование запросов

`prompts/`

Назначение:
* построение текстов запросов к модели;
* поддержка одиночных запросов и батчей;
* задание формата ответа.

---

## 4.6 Защита токенов

`protection/`

Назначение:
* временная замена чувствительных элементов (переменные, теги);
* сохранение информации для восстановления;
* обратное восстановление после перевода.

---

## 4.7 Валидация

`validation/`

Назначение:
* проверка корректности ответа модели;
* разбор структурированных данных;
* обнаружение ошибок;
* сигнал о необходимости повторного запроса или перехода в одиночный режим.

---

## 4.8 Хранение данных

`storage/`

Назначение:
* работа с SQLite;
* сохранение результатов эксперимента;
* хранение попыток вызова модели;
* хранение метрик.

Особенности:
* прямые SQL-запросы (тут без ORM)

---

## 4.9 Оценка и отчёты

`evaluation/`

Назначение:
* вычисление метрик качества перевода;
* вычисление классических метрик (BLEU, chrF, TER, COMET);
* анализ стабильности работы API;
* расчёт эффективности использования токенов;
* построение сводных отчётов и лидербордов.

---

## 4.10 Дополнительные модули

* `domain/` — общие структуры данных
* `datasets/` — загрузка наборов данных
* `legacy_bridge/` — адаптеры для старой логики
* `utils/` — вспомогательные функции

# 6. Модель хранения данных

Основные таблицы:
* experiments — информация об эксперименте;
* results — итоговые переводы;
* attempts — попытки вызова модели (для конкретной строки);
* metrics — метрики качества;
* api_metrics — метрики работы API;
* classic_metrics — классические метрики;
* cache — кэш переводов.

---

# 7. Расширение системы

Добавление новых компонентов выполняется через реестры. Это нужно чтобы при необходимости расширять доступные варианты для конфига.

**Добавление модели**
* реализовать интерфейс runtime;
* зарегистрировать в реестре.

**Добавление шаблона запроса**
* реализовать профиль;
* зарегистрировать в реестре.

**Добавление стратегии защиты**
* реализовать интерфейс;
* зарегистрировать в реестре.

**Добавление валидатора**
* реализовать интерфейс;
* зарегистрировать в реестре.

**Добавление метрик**
* реализовать расчёт;
* при необходимости добавить таблицу;
* подключить в отчётах.

# 8. Концептуальная модель

Система состоит из независимых слоёв:
* CLI — вход пользователя
* config — описание эксперимента
* translation — выполнение перевода
* prompts — формирование запросов
* protection — защита текста
* runtime — взаимодействие с моделью
* validation — проверка ответа
* storage — хранение
* evaluation — вычисление метрик
* reporting — построение отчётов
* legacy_bridge — совместимость с прошлой логикой (я правда подуал что так будет проще, но вышло не так)
